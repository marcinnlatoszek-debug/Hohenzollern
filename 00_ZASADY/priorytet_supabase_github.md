## Treść zatwierdzonej zasady

Od 17 października 2026 r. w projekcie „Nobilis gens von Hohenzollern” głównym, trwałym rejestrem danych kampanii i obowiązujących, zatwierdzonych ustaleń jest baza Supabase (projekt Hohenzollern, schemat chronicle). W każdej nowej analizie, aktualizacji kanonu, chronologii, kart postaci, genealogii, strategii i przygotowaniu materiałów dla Astry należy najpierw sprawdzić Supabase i datę/status odpowiednich rekordów. GitHub (marcinnlatoszek-debug/Hohenzollern) jest kopią zapasową i źródłem awaryjnym; gdy baza jest niedostępna lub odpowiedni wpis nie został jeszcze do niej wprowadzony, można skorzystać z GitHuba, wyraźnie oznaczając datę i ograniczenia wersji. Po przywróceniu dostępu należy zweryfikować rozbieżności i uzupełnić brakujące dane w bazie bez bezśladowego nadpisywania.

Priorytet miejsca przechowywania nie zmienia hierarchii dowodów: najnowszy wiarygodnie odczytany save CK3, zrzuty ekranu i jednoznaczne potwierdzenia użytkownika stanowią podstawę ustalania faktów; sama obecność informacji w Supabase ani GitHubie nie oznacza jej prawdziwości lub akceptacji do kanonu. Nowe wydarzenia i ważne zmiany kanoniczne wymagają wyraźnej zgody użytkownika. Wpisy robocze, interpretacje, prognozy i proza muszą pozostawać oddzielone od faktów i zatwierdzonego kanonu.

Przed zapisem nowego stanu należy porównać daty gry, tożsamości i źródła. Zachowywać starsze obserwacje i historię zmian. GitHub przechowuje awaryjną kopię zasad i materiałów, jednak synchronizacja nie jest automatyczna; każda operacja aktualizacji wymaga rzeczywistego zapisu oraz kontroli wyniku. W razie konfliktu między bazą a GitHubem nie wolno automatycznie przyjmować nowszego lub wygodniejszego wpisu: sprawdzić źródła, status akceptacji i datę, a niejasność oznaczyć jako NIEUSTALONE do rozstrzygnięcia przez użytkownika. Ta zasada zastępuje wcześniejsze instrukcje określające GitHub jako podstawową pamięć roboczą projektu, ale nie zmienia zasad fabularnych ani faktów historycznych świata gry.

## Procedura praktyczna

1. Weryfikację, analizę, kanon, genealogię, kronikę i briefy dla Astry zaczynaj od sprawdzenia `chronicle.v_active_project_policies` oraz właściwych danych w Supabase.
2. W razie braku dostępu do Supabase lub brakującego rekordu sięgnij do GitHuba, ze wskazaniem źródła i daty ostatniej aktualizacji.
3. Jeśli występuje rozbieżność, sprawdź rzeczywisty zapis CK3, screeny i zatwierdzenia. Nie nadpisuj ani nie ustanawiaj faktów domyślnie.
4. Dopiero po wyraźnym zatwierdzeniu przez użytkownika aktualizuj wiążący kanon w Supabase; zachowaj historię zmian i odnośniki do źródeł.
5. GitHub może przechowywać oddzielnie aktualizowane archiwalne kopie. **Nie zakładaj automatycznej synchronizacji**, dopóki nie zostanie odrębnie wdrożona i sprawdzona.
